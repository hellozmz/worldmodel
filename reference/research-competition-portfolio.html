Reference

Research & Competition Portfolio

把比赛、论文和 benchmark 复现当成三条可切换出口，而不是把学习绑在一个截止日期上。

核心原则

一个能力池

数据审计、baseline、world model、policy、闭环评估、失败分析，先沉淀成可复用实验组件。

三个出口

Challenge 看官方指标；paper 看研究问题；benchmark report 看协议和复现性。

随时可切换

官方窗口关闭时，改投 workshop、整理 technical report，或做公开 benchmark 复现。

证据优先

排行榜分数只是证据之一；无协议、无 baseline、无 seed 的分数不能变成研究结论。

当前默认组合

RoboWorld WorldNav 是默认 challenge 路线；同时维护一条 workshop paper / technical report 线和一条 benchmark reproduction 线，避免错过一个窗口后成果没有落点。

三条产出线

Track你要回答最小交付物风险
Challenge submission官方指标是否提高，提交是否合法？规则记录、baseline、validation 结果、submission log、技术报告窗口、数据体量、格式、资格和服务器评分的不确定性
Workshop paper / technical report问题是否清楚，证据是否支撑 claim？问题定义、协议、多 baseline、多 seed、消融、失败分析、limitations实验规模不足或贡献被表述成过度 claim
Benchmark / reproduction report结果能否被别人复现，误差来自哪里？协议、环境、配置、命令、结果表、敏感性分析需要耐心整理工程细节，短期曝光可能较低

机会筛选表

报名或投稿前逐项填写。任何一项无法满足，就先降级为观察项或寻找替代出口。

维度必须确认不合格时的处理
Data能否合法下载？大小多少？split 是否明确？字段和单位是否可审计？改用公开小规模 benchmark 或最小子集复现
Compute fit训练、微调、推理分别需要多少 GPU / 显存 / 时间？缩小模型、减少 seed 中的探索实验、只保留正式 3 seed
Baseline官方或公开 baseline 是否可复现？有没有至少三个可比对象？先完成 reproduction report，不做方法改进
Official metric主指标、tie-break、test server 限制、外部数据规则是什么？切换到协议清晰的公开 benchmark
Reproducibility配置、seed、环境、命令、checksum 能否固定？先补实验记录，不进入写作阶段
Time budget距离 deadline 是否至少有复现 + 改进 + 失败重启三轮时间？转下一届、workshop report 或内部技术分享
Value得到的是排名、研究问题、公开资产，还是工程能力？若三者都不是，归档为 rejected_ideas

去哪里找新机会

Conference workshops

CVPR、ICCV、ECCV、NeurIPS、ICLR、CoRL、ICRA、IROS 的 workshop / challenge 页面。

Challenge 平台

CodaBench、EvalAI，按 robotics、embodied AI、world model 检索。

OpenReview

OpenReview 查 workshop CFP、审稿标准、接收论文和常见问题定义。

Paper discovery

arXiv 找新方法；Papers with Code 找代码、数据集和 baseline。

Embodied AI hubs

Embodied AI Workshop、AI Habitat、BEHAVIOR、LeRobot。

官方 GitHub

比赛 repo 的 README、issue、release 和 submission template 常比二级新闻更可靠。

最低实验标准

Publishable / submission-ready checklist

至少 3 个 baseline；至少 3 个正式 seed；episode-safe train/validation/test split；offline 与 closed-loop 指标分列；seen/unseen 结果分列；关键 ablation；latency、显存和训练成本；失败案例分类；精确命令、配置和随机种子。
