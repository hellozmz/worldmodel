Reference

评价体系：从接口测试到闭环证据

同一个数字，在不同协议下证据强度完全不同。

三级证据阶梯

1. Interface smoke test

验证依赖、张量形状、设备、推理流程能跑通。

能证明：接口正确。
不能证明：任务性能。

2. Offline metric

在留出数据上计算 MSE、PSNR、SSIM、LPIPS、rollout error 等。

能证明：拟合和预测能力。
不能证明：交互中的任务成功。

3. Closed-loop evaluation

把模型动作送回仿真器或真机，观察未来观测变化。

能证明：控制能力和误差累积下的稳定性。
仍依赖：环境分布、种子数量和 baseline。

World model 常用指标

指标衡量什么注意点
PSNR像素级重建误差高 PSNR 不等于语义或物理正确。
SSIM结构相似性对亮度、对比度、结构更敏感，但仍是图像级指标。
LPIPS深度特征感知差异更接近视觉感知，但依赖特征提取器。
FVD视频分布质量需要足够样本；不同实现可能不可直接比较。
Rollout error vs horizon误差随预测步数累积的情况比单点 validation loss 更关键。
Temporal consistency帧间物体和相机是否稳定可结合物体跟踪或人工评价。
Action controllability动作改变是否按预期改变未来区分“好看视频”和“可控世界模型”。
Physical plausibility碰撞、重力、接触是否符合规律常见于人工协议或专门 benchmark。
Latency / throughput生成或一步预测耗时实时规划和真机控制必须报告。
Sample efficiency达到目标所需交互或数据量对真实机器人尤其重要。
Generalizationunseen scene / task / embodiment 表现必须在官方 split 或明确划分上测试。

Policy / VLA 常用指标

指标含义陷阱
Success rate成功 episode 数 / 总 episode 数必须说明 episode 终止条件和随机种子。
Return奖励累计奖励 shaping 可能与人类理解的任务完成不一致。
Completion / progress任务完成度长时序任务中比二值成功更细。
Coverage目标覆盖率，PushT 常用覆盖率提升不等于达到成功阈值。
SPL导航成功率和路径效率的联合指标只适用于有最短路径定义的导航任务。
Action MSE预测动作与数据动作差异低 offline MSE 可能只是学会平滑轨迹。
Chunk erroraction chunk 内逐步误差要区分首步误差和远步误差。
Latency首次推理和 warmed-up 推理时间真机控制要报告控制频率。
Model size / memory参数量、显存、能耗部署限制下与成功率同样重要。
Robustness扰动、遮挡、光照、语言变化不能只用训练分布测试。
Safety碰撞、力限、干预率真机实验必须有安全协议。

实验设计检查表

  1. 数据划分：按 episode split，不能把同一轨迹的相邻帧分别放进训练/验证。
  2. Baseline：至少包含 random、previous action、简单监督模型或官方 baseline。
  3. 种子与方差：报告 mean ± std 或多次 run；不要用单次最好结果。
  4. 指标分层：同时报告 offline 和 closed-loop，不能混用结论。
  5. 泛化：标明 seen / unseen scene、task、object、embodiment。
  6. 算力：GPU 型号、训练时间、推理延迟、显存。
  7. 失败判据：提前写清什么结果会推翻假设。
  8. 证据文件：保存命令、配置、JSON、图像、视频和随机种子。

核心警示

Offline 指标低但闭环失败，通常来自 distribution shift 和 error accumulation：闭环中模型自己的动作会改变后续观测，不再永远停留在数据分布内。
